### **1. AWS Database Migration Service (DMS) Overview**

### **2. AWS Snowball for Data Migration**

**AWS Snowball**:
- **Use Case**: Large data migrations (petabytes) when network bandwidth is insufficient.
- **Process**: Data is transferred to a physical Snowball device, shipped to AWS, and uploaded to S3.

**Common Issues**:
- **Error**: Snowball device delays.
  - **Resolution**: Track shipping status through the AWS Console and ensure correct device handling on-site.
- **Error**: Data transfer interruptions.
  - **Resolution**: Confirm local network stability and device compatibility before initiating the data transfer.

### **Final Notes on AWS Profiles and Access**

When working with AWS resources like EC2 and RDS across multiple accounts or environments, it’s crucial to set up **AWS profiles**. These profiles are configured in the AWS CLI using the `aws configure` command, allowing you to switch between different accounts without manually changing access credentials.

- **Setting AWS Profile**: You can specify the AWS profile in your Terraform or AWS CLI configuration by setting the `AWS_PROFILE` environment variable. Example:
  ```bash
  export AWS_PROFILE=your_profile_name
  ```

- **Common Issues with AWS Profile**:
  - **Error**: "No credentials found for the specified profile."
    - **Resolution**: Ensure that the correct profile is set in the environment variable and that the credentials exist in the `~/.aws/credentials` file.
  - **Error**: "Access Denied"
    - **Resolution**: Ensure the IAM role associated with the profile has the required permissions to interact with EC2, RDS, etc.
